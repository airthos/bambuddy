# Bambuddy Repository Audit — June 2026

Read-only audit of the full repository: backend (FastAPI, ~110K lines), frontend (React 19 + TypeScript, ~200K lines), Docker/CI/dependencies, and repo hygiene. Every High/Medium finding was verified against the actual source; file:line references point at the audited revision (`e878ec7`). No code was changed — this is a report only.

Severity is calibrated to the deployment reality: a self-hosted LAN application, frequently run with authentication disabled by choice, controlling physical hardware (printer farms, smart plugs).

---

## Executive summary

**Overall health: strong.** This is a mature, security-conscious codebase with practices well above the open-source norm: hashed API keys with JTI revocation, Fernet encryption for TOTP/OIDC secrets, consistent DOMPurify with an XSS regression test, nonce-based CSP, SSRF guards, list-based subprocess calls, consistent path-containment checks, exemplary `.trivyignore`/gitleaks hygiene, and CI that lints, type-checks, tests (sharded), and scans on every push. Nearly every past bug fix carries its issue number in a comment.

The material risks are concentrated in two areas:

1. **Async-runtime reliability** — fire-and-forget background tasks, blocking work on the event loop, and a fragile MQTT thread boundary. These can manifest as: the print queue silently stopping forever, a printer staying powered on after a failed auto-off, all printers "freezing" while a large archive is processed, or 60+ seconds of blind dispatch after a malformed printer payload.
2. **Migration safety on SQLite** — legacy table rebuilds swallow all errors and SQLite DDL is not actually transactional under the current driver settings, so a crash or lock at the wrong moment can silently skip a migration or, worst case, lose a table.

### Top 5 findings

| # | Finding | Severity |
|---|---------|----------|
| 1 | Print scheduler runs as an unsupervised fire-and-forget task — if it dies, dispatch stops silently forever (`main.py:4971`) | High |
| 2 | An unexpected exception parsing a printer MQTT payload kills the paho network thread *and* auto-reconnect (`bambu_mqtt.py:786-788`) | High |

## High-severity findings

### H1 — Print scheduler task is fire-and-forget and unsupervised
`backend/app/main.py:4971`
```python
asyncio.create_task(print_scheduler.run())
```
No reference is held (the event loop keeps only weak refs — the task is GC-collectable mid-run), nothing observes its exception, and nothing restarts it. The loop body in `services/print_scheduler.py:109-120` catches `Exception` per iteration, but the `await asyncio.sleep(...)` at line 120 sits *outside* the try — a `CancelledError` (including GC-driven) there kills the loop permanently. `stop()` only flips a flag; the task is never cancelled/awaited at shutdown, so it can wake mid-teardown against a disposed DB engine. **Impact:** the queue silently stops dispatching with no log. **Fix:** store the task (`self._task = asyncio.create_task(...)`), add a done-callback that logs `task.exception()` and restarts, and `cancel()` + `await` in shutdown.

### H2 — Smart-plug power-off task can vanish, leaving the printer powered
`backend/app/main.py:3451`
```python
asyncio.create_task(cooldown_and_poweroff(printer_id, [p.id for p in enabled_plugs]))
```
Per-plug `turn_off` errors are caught, but `await printer_manager.wait_for_cooldown(...)` (line 3434) is outside any try, and the Task object is unreferenced. If GC collects it or the cooldown wait raises, **the printer stays powered on** with only a late "Task exception was never retrieved" message. Same class of problem at six more per-print-completion sites — see M5. **Fix:** a shared `_bg_tasks: set[asyncio.Task]` (`_bg_tasks.add(t); t.add_done_callback(_bg_tasks.discard)`) plus try/except-log in the body.

### H3 — One bad MQTT payload kills printer telemetry and auto-reconnect
`backend/app/services/bambu_mqtt.py:786-788`
```python
self._process_message(payload)
except json.JSONDecodeError:
    pass  # Ignore non-JSON MQTT messages
```
`_process_message` → `_update_state` is ~1,000 lines of firmware-payload parsing; only the AMS branch is individually wrapped. paho-mqtt 2.x re-raises callback exceptions by default (`suppress_exceptions=False`), terminating the network thread — so one `TypeError`/`KeyError` from a new firmware's payload shape stops all telemetry *and* paho's auto-reconnect for that printer. Recovery is passive: only after the 60s `STALE_TIMEOUT` *and* a `get_status` call. **Fix:** wrap `_process_message` in `except Exception: logger.exception(...)`; optionally set `suppress_exceptions = True` as a backstop. Keep the JSON-decode ignore scoped to `json.loads` only.

### H4 — `loop_stop()` thread-joins run on the event loop
`backend/app/services/bambu_mqtt.py:581` (`_hard_reset_client`), `:3684` (`disconnect`); callers include `check_staleness()`, `PrinterManager.disconnect_printer` (`printer_manager.py:429-432`), routes `printers.py:309/341/756`, and shutdown `disconnect_all()`.
paho's `loop_stop()` joins the network thread with no timeout; mid-TLS-handshake against an unresponsive printer this takes up to ~5s — during which the entire event loop (every HTTP request, WS broadcast, and the dispatch scheduler for the whole farm) is frozen. The project already diagnosed this exact failure as #1445 and fixed it **only** in `test_connection` (`printer_manager.py:676-679` uses `asyncio.to_thread`). **Fix:** push the `disconnect()`/`loop_stop()` teardown to `asyncio.to_thread` in `_hard_reset_client` and `disconnect_printer` as well.

### H5 — Archive pipeline blocks the event loop for the whole farm
`backend/app/services/archive.py:1094` (`_copy_and_fsync`), `:1132` (`compute_file_hash`), `:1144` (`ThreeMFParser.parse()`), inside `async def archive_print`.
A several-hundred-MB `.gcode.3mf` means full copy + fsync + SHA256 + ZIP parse, all synchronous on the loop — called from the scheduler tick (`print_scheduler.py:2024`), background dispatch (`background_dispatch.py:775`), and upload routes (`archives.py:3002/3053`). While it runs, all printers appear to freeze. **Fix:** mechanical — wrap the copy/hash/parse in `asyncio.to_thread` (they're already pure-sync functions). Related blocking-on-loop sites: 3MF read+zip parse in MQTT handlers (`main.py:2732-2736`, `:1749-1752`), PIL snapshot rotation (`main.py:1654-1658`).

### H6 — Library upload/extract endpoints block the loop and buffer whole files in RAM
`backend/app/api/routes/library.py:1603-1679` (`upload_file`: whole upload via `await file.read()`, sync write, sync SHA256, sync 3MF parse, then `generate_stl_thumbnail` — a synchronous trimesh+matplotlib render taking 1–5s per file), `:1872-1934` (`extract_zip_file`: same per ZIP entry), `:634-645` (STL thumbnail backfill — moved to a background *task* for #1299, but a task still runs on the loop: thousands of NAS STLs × 1–5s each). Multiple upload endpoints across `archives.py`/`library.py` buffer multi-hundred-MB bodies in RAM (`archives.py:2257/2375/2475/2992/3040`, …) — an OOM risk on the Raspberry-Pi-class hosts the project explicitly targets. **Fix:** stream uploads to disk in chunks; offload hash/parse/render with `asyncio.to_thread`.

### H7 — Legacy SQLite table rebuilds can silently skip migrations or lose data
`backend/app/core/database.py:952-990` and `1107-1155` (`print_queue` rebuilds), `1022-1080` and `1229-1310` (`smart_plugs` rebuilds) — each a CREATE-new → copy → `DROP TABLE` → RENAME sequence wrapped in:
```python
except (OperationalError, ProgrammingError):
    pass  # Already applied
```
No savepoint, no defensive `DROP TABLE IF EXISTS ..._new`, no row-count verification — any error (including "database is locked" during startup) is treated as "already applied". If the CREATE succeeds but the copy fails, the orphan `_new` table makes every future attempt fail-and-swallow: the migration is *permanently, silently* never applied. Compounding this, **SQLite DDL is not actually transactional here**: the engine (`database.py:26-38`) lacks the documented SQLAlchemy pysqlite workaround, so DDL autocommits statement-by-statement and the outer `engine.begin()` (`:217-221`) does not protect rebuilds — the code's own comment at `:2373-2375` ("a previous startup may have crashed mid-rebuild") confirms this happens. Worst case: crash between DROP and RENAME → `create_all` recreates an **empty** table next boot. The newer rebuilds (`:483-535`, `:585-632`, `:2371-2410`) already do it right (defensive drop, row-count check that raises, logged re-raise). **Fix:** retrofit that pattern onto the four legacy rebuilds; install the pysqlite `connect`/`begin` event workaround for transactional DDL; longer term, adopt a migration ledger (or Alembic) — today ~200 statements re-execute on every startup with no record of what was applied (`:635-2666`).

### H8 — No lockfile for production Python dependencies; dev tools in the production image
`requirements.txt` is floor-pins only (`fastapi>=0.109.0`, …) and the Dockerfile installs straight from it (`Dockerfile:55-58`) — every image build pulls whatever is newest on PyPI, so a bad or compromised upstream release ships silently, and CI's scan results describe a different dependency set than any published image. Additionally `requirements.txt:86-90` contains a `# Development` block (`pytest>=9.0.3`, `pytest-asyncio`, duplicate `httpx`, `ruff`) that contradicts `requirements-dev.txt` and installs test tooling into the production image. **Fix:** hash-pinned lock (`pip-compile --generate-hashes` or `uv lock`) consumed by the Dockerfile; delete lines 86-90.

### H9 — Known-vulnerable `react-router`, and the CI gate that would catch it can't block
`frontend/package-lock.json:6776` resolves react-router **7.13.0**: 6 advisories incl. GHSA-49rj-9fvp-4h2h (turbo-stream RCE — framework/SSR mode, so reduced impact for this SPA) and an open redirect, fixed in ≥7.14.3. The `frontend-security` CI job's "fail on fixable high/critical" filter (`ci.yml:198-204`) would exit 1 on this today — but both security jobs carry `continue-on-error: true` (`ci.yml:57`, `:167`), so they can never block a merge. **Fix:** `npm update react-router react-router-dom` now; remove `continue-on-error` (the ignore-list mechanism already exists for accepted findings). Dev-only but worth bumping at the same time: vitest < 3.2.6 (critical advisory, exploitable only via `npm run test:ui`).

## Medium-severity findings

### Security

**M1 — WebSocket telemetry is unauthenticated even when auth is enabled.** `backend/app/api/routes/websocket.py:13-18` accepts any connection with no token/permission check and streams full state for all printers (plus answers `get_status` for any printer id). The gateway auth middleware is `@app.middleware("http")` (`main.py:5308`) and never runs on WebSocket scope. Read-only (no print control), hence Medium. **Fix:** validate a camera-stream-style ephemeral token (the mechanism already exists — `verify_camera_stream_token`) before `ws_manager.connect()`; the frontend hook already has `getAuthToken()` available (`frontend/src/hooks/useWebSocket.ts:73-75`).

**M2 — Long-term device credentials stored in plaintext while comparable secrets are encrypted.** Printer access codes (`models/printer.py:16`), smart-plug username/password (`models/smart_plug.py:99-100`), and settings values (`mqtt_password`, `ha_token`, `ldap_bind_password`, `smtp_password`, …) are plaintext in the DB; TOTP secrets and OIDC client secrets already go through `core/encryption.py` (Fernet). Realistic threat is leaked/shared **backups** (the DB is included in backups). **Fix:** route these columns through the existing `mfa_encrypt`/`mfa_decrypt` helpers via model properties, same pattern as `UserTOTP`.

**M3 — Stored `external_url` opened without scheme validation or `noopener`.** `frontend/src/pages/ArchivesPage.tsx:439-440` (and 1198, 1793, 2173): `window.open(url, '_blank')` on a free-form string — backend schema is plain `str | None` (`schemas/archive.py:15,83`). In multi-user deployments a user with `archives:update` can store `javascript:...` that executes in another user's session; `window.open` without the third argument also leaks `window.opener`. Other call sites do it right (`Layout.tsx:457`). **Fix:** allow only `http(s):` and pass `'noopener,noreferrer'`; add scheme validation (`pydantic.HttpUrl`) on the backend.

**M4 — Default deployment exposes the full unauthenticated API to the LAN.** `docker-compose.yml:23` uses `network_mode: host` (needed for discovery) and `is_auth_enabled()` defaults to `False` when unset (`core/auth.py:473-483`) — so out of the box, the web API, virtual-printer MQTT, FTPS, and RTSP are reachable by anyone on the LAN, including printer access codes and file upload/delete. SECURITY.md says "trusted network", but the compose file never states the consequence. **Fix:** a warning comment at the `network_mode` line and/or a first-run prompt to enable auth.

### Reliability

**M5 — Six more bare per-print-completion tasks.** `main.py:3945, 4126, 4127, 4145, 4184, 4194` (energy calculation, smart-plug auto-off, maintenance check, finish-photo→notification chain, layer timelapse, timelapse scan). Bodies log their own exceptions, but the Task objects are unreferenced — GC mid-run silently drops energy data, the completion notification, or auto-power-off. The `photo_task` chain (`:3947` + `:4134`) is held only by the closure of another bare task. The no-op `add_done_callback(lambda _t: None)` at `:3636-3637` neither retrieves the exception nor keeps the task alive. **Fix:** same `_bg_tasks` set as H2.

**M6 — Shutdown cancels but never awaits background loops.** Every `stop_*` in `main.py` (e.g. `:4401-4407`) does `task.cancel()` and drops the reference; lifespan never awaits them, so a loop mid-DB-write races `engine.dispose()` (`:5088`). The scheduler task and in-flight per-print tasks (up to 10-minute cooldown waits) are never cancelled at all. **Fix:** `task.cancel()` then `await asyncio.gather(*tasks, return_exceptions=True)` before DB/MQTT teardown.

**M7 — Live mutable dicts shared across the MQTT thread boundary.** The paho thread mutates `state.temperatures` in place (`bambu_mqtt.py:2457, 2477, 2493`) while the event loop iterates it and embeds the **live dict reference** into WS/API responses (`printer_manager.py:946-962`) — intermittent `RuntimeError: dictionary changed size during iteration` → dropped broadcasts/stale cards. Same shape for `hms_errors` (`bambu_mqtt.py:2499+`). The codebase already uses the correct copy-then-atomically-replace pattern for `raw_data["ams"]` (`:1847, 1911`) — extend it. Note the callback→asyncio handoff itself (`printer_manager.py:346-364`) is done correctly everywhere, with done-callback exception logging.

**M8 — Scheduler swallows archive-creation failure for library prints.** `print_scheduler.py:2040-2041` logs a warning and proceeds to print with no archive row (a `None` return isn't even logged) — silent loss of usage tracking, spool deduction, and reprint history for that job. **Fix:** surface on the queue item or notify; handle the `None` return explicitly.

**M9 — Dispatch silently prints plate 1 on unreadable 3MF.** `background_dispatch.py:1083-1084` swallows `ValueError/BadZipFile/OSError` in `_resolve_plate_id` and falls back to plate 1 — for a multi-plate file this prints the wrong plate with no log line. **Fix:** log at warning; consider failing the job.

**M10 — Duplication has already bred a real bug.** The print-start acknowledge watchdog exists in two copies; the scheduler version has the `state != "IDLE"` rejection-echo guard (`print_scheduler.py:2453`, the P1S false-positive fix) that `background_dispatch.py:1011` (`_verify_print_response`) **lacks**. Other large duplications: ~270-line plate-listing endpoint (`library.py:2201-2470` vs `archives.py:3084-3370`), preview-slice helper (verbatim, admitted in its docstring), plate-thumbnail and filament-requirements endpoints, two SHA256 helpers, `clean_metadata` ×4 in library.py alone, printer-lookup/404 boilerplate 40+ times repo-wide. **Fix:** port the IDLE guard now; consolidate the shared endpoint logic into services.

**M11 — Migration hygiene beyond H7.** `_safe_execute` swallows `"no such column"` for *all* DDL, hiding skipped-index schema divergence (`database.py:399-401`); the LDAP `password_hash` migration edits `sqlite_master` via `PRAGMA writable_schema` with non-fatal failure handling (`:1927-1949` — a corruption-capable tool); a swallowed `IntegrityError` can silently discard legacy virtual-printer config (`:1681-1682`); and there is no cross-instance migration lock (two containers sharing one DB can interleave rebuilds, `:217-221`).

**M12 — Database restore ignores HTTP errors in the frontend.** `frontend/src/api/client.ts:4304-4322` (`importBackup`): no `response.ok` check on the most dangerous operation in the app — a 4xx/5xx during restore surfaces as a shape-mismatched object or opaque parse error. Four other hand-rolled fetch paths bypass the shared `ApiError`/401 handling (`:4180-4221`, `:4278-4303`, `:3558`). **Fix:** a shared `requestMultipart()` helper.

**M13 — PrinterCard is a 4,140-line component re-rendered up to 10×/second.** `PrintersPage.tsx:1433-5573` is one component with ~14 internal `useQuery` hooks; the page bumps a counter for *any* `printerStatus` cache update (`:6979-6991`), re-rendering every unmemoized card (zero `memo()` in the file) up to every 100ms while any printer prints — the WebSocket layer's careful throttling (`useWebSocket.ts:130-160`) is undone for large fleets. **Fix:** extract AMS/plate-detection/drying/firmware sections, `React.memo(PrinterCard)`, and bump the version only on meaningful state changes.

**M14 — CI is skipped for the owner's own PRs, and releases aren't built in CI.** Every job carries `if: github.event.pull_request.user.login != github.repository_owner` (`ci.yml:35` etc.) — owner PRs merge with zero recorded checks. Images are published from a maintainer's machine via `docker-publish*.sh` (no provenance, no signing, no scan of the actual published artifact). **Fix:** drop or narrow the owner condition; add a tag-triggered publish workflow with Trivy on the built digest.

## Low-severity findings (abridged)

**Backend security**
- Two 3MF XML parse sites use stdlib `ElementTree` instead of defusedxml (`services/filament_requirements.py:19,53`, `services/virtual_printer/manager.py:551,557`). Not an XXE file-read primitive on modern CPython — residual risk is entity-expansion DoS via authenticated upload. Swap for consistency.
- ZIP extraction has no decompression-size cap (`library.py:1862-1874`) — zip-bomb DoS via authenticated upload (note: *not* zip-slip; destinations are server-generated UUID names). Check `zf.getinfo(...).file_size` before `read`.
- Auth check and gateway middleware fail open on DB error (`core/auth.py:481-483`, `main.py:5347-5349`) — a deliberate availability trade-off; consider fail-closed once the DB is known-initialized.
- Metrics token compared non-constant-time (`api/routes/metrics.py:78`) → `secrets.compare_digest`.
- External MQTT relay/smart-plug brokers disable TLS verification unconditionally (`mqtt_relay.py:124-125`, `mqtt_smart_plug.py:147-148`) — make it a toggle, default on.
- `archives.py:2505-2506` (`get_photo`): user-supplied `filename` joined without the `filename in archive.photos` membership check its sibling `delete_photo` has.
- Bearer tokens in Web Storage (`client.ts:36-61`) — standard SPA trade-off, but one DOMPurify bypass = account takeover; the HttpOnly-cookie plumbing already exists (2FA challenge).
- 401 handling matches English message substrings (`client.ts:157-163`) — use the structured error code instead.
- `escapeValue: false` + five `__html: t(...)` sites (`PrintersPage.tsx:4955+`) is safe only while those keys have no `{{placeholders}}` — add a guard rule.

**Backend reliability**
- ~35 single-statement migration blocks treat any `OperationalError` (incl. "database is locked") as "already applied" (`database.py:705-2336`) — route through `_safe_execute`.
- SQLite pool config allows 220 concurrent connections to one file (`database.py:28-29`) — cap it.
- `_on_connect` refusal (wrong access code) is completely silent (`bambu_mqtt.py:657-658`); failed hard-reset reconnect is never retried (`:589-592`); `_schedule_async` silently drops events when the loop isn't running (`printer_manager.py:352`).
- Non-atomic `self._sequence_id += 1` from two threads (`bambu_mqtt.py`); `disconnect(timeout=0)` makes the graceful-disconnect wait a no-op on every default call (`:3678-3686`).
- 12 `except Exception: pass` blocks in `main.py` (list at 774…4181); the two worth fixing log nothing where data is lost: AMS-mapping injection (`:2087-2095`) and queue-completion notification (`:3420`).
- 127 function-level imports (105 `from backend.*`), incl. `get_setting` imported from a *route* module 10+ times and a private `_active_sessions` cross-module import (`main.py:2088`) — move `get_setting` to core, hoist model imports.
- Temp-file leak on early failure in `library.py:1762-1768`; fixed temp names collide for concurrent edits (`archives.py:2380-2389`).

**Frontend**
- Pages with zero tests: `UsersPage`, `SetupPage` (both security-relevant), `ProfilesPage`, `GCodeViewerPage`, `ExternalLinkPage`. Coverage configured but no thresholds and never run in CI.
- Hardcoded English bypassing the (excellent) i18n parity gate: `ProjectPageModal.tsx` (no `useTranslation` at all), `RichTextEditor.tsx:97`, `PendingUploadsPanel.tsx:135,144`.
- All 9 locale bundles (~6K lines each) are imported eagerly (`src/i18n/index.ts:6-14`) — lazy-load per locale.
- `minimatch` override forces a 7-major-version jump on dev-tool transitives with no documented rationale (`package.json:46-48`).

**Infra / CI / hygiene**
- Actions pinned by tag, not SHA; no `dependabot.yml` at all (actions/pip/npm).
- pip-audit ignore lists differ between `ci.yml:82-84` and `security.yml:140-145` — the weekly job will perpetually re-file an already-triaged alert.
- `test_frontend.sh` can never fail (no `set -e`; last command is `cd ..`), silently breaking `test_all.sh`; `test_backend.sh` discards the ruff exit status. The install/update scripts, by contrast, are exemplary (`set -Eeuo pipefail` + rollback).
- `setcap cap_net_bind_service` on the python binary (`Dockerfile:49`) lets any compromised process bind any privileged port — on host networking, that's the host. Consider the `ip_unprivileged_port_start` sysctl instead. HEALTHCHECK runs as root (no `USER` directive); PUID/PGID unvalidated; floating base-image tags.
- Stray files: `backend/=0.9.0` (0-byte shell-redirect accident from the pytest-split install) and `.coverage` (69KB binary) are committed; `.gitignore` misses `.coverage*`. 6.8MB of built frontend output is committed per release (history bloat).
- Version drift: `pyproject.toml` says `0.1.5`, app is `0.2.4.3` (`core/config.py:9`). `.env.example` still says "BambuTrack" and is disjoint from the env vars docker-compose documents.
- Vendored `gcode_viewer/` bundles three.js **r108** (Sept 2019, properly documented in VENDORED.md) — no known exploitable CVE for this usage, but the frontend already ships `three@0.181`; consolidate.
- JWT secret regenerates per restart only if `DATA_DIR` is unwritable (logged) — document `JWT_SECRET_KEY` for multi-worker setups.

## What's already done well

- **Auth stack:** pbkdf2 hashing everywhere (passwords, API keys, long-lived tokens), JWT alg pinned, JTI revocation surviving restarts, token-freshness invalidation on password change, TOTP replay protection, login/MFA rate limiting, API keys blocked from admin operations, consistent `RequirePermissionIfAuthEnabled` gating across route files.
- **Encryption lifecycle** (`core/encryption.py`): `O_EXCL`+0600 key creation, refusal to overwrite a corrupt key, surfaced re-encryption error counts.
- **Hardening:** nonce-based CSP, nosniff/Referrer-Policy/XFO/HSTS, no CORS middleware (same-origin), SSRF guards with metadata/loopback/private-range blocking on user-URL paths, `shlex.quote`d SSH, list-only subprocess, consistent `resolve()`+`is_relative_to` path containment with loud SECURITY logs, FTP/MQTT emulation requiring the access code.
- **Frontend:** DOMPurify on every user-HTML render *with a regression test*, session-fixation-aware kiosk token bootstrap, structured error codes → i18n keys, near-zero `any` under `strict: true`, sophisticated WebSocket backpressure handling, best-in-class AST-based i18n parity gate (4,993 keys × 9 locales, enforced in CI).
- **Ops:** well-documented multi-stage Dockerfile with gosu privilege drop, exemplary `.trivyignore` with reachability justifications, least-privilege workflow permissions, weekly security audits that auto-open *and auto-close* tracking issues, every historical bug fix annotated with its issue number (#967, #1032, #1136, #1299, #1445…), `get_db`'s cancellation-safe session cleanup, WAL+busy_timeout+synchronous pragmas, the newer migration-rebuild pattern with row-count verification.
